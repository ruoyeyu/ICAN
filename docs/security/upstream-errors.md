# 上游错误详情

自定义 API 的创建、轮询和鉴权下载共用服务端错误解析与脱敏。优先提取 `error.message`、`detail`、`message`、`msg`，支持嵌套 JSON 字符串；非 JSON 内容作为文本处理。没有有效详情时才使用通用提示。模型、prompt、参数和鉴权配置不变。

现有失败详情窗口显示脱敏后的完整正文，以及 HTTP 状态、失败阶段和上游 request ID。主提示保留摘要。错误正文读取边界为 256 KiB，超出时返回 `truncated: true` 并明确标注截断；未超出的正文不会再受摘要长度限制。JSON 仅格式化和脱敏，不执行其中的内容。

已知渠道 Key、敏感请求头、凭据字段、素材 Data URL 和链接隐藏。详细响应只通过当前账号的请求或其任务记录返回；自定义视频任务不存在或不属于当前账号时，不能绕过任务归属检查直接查询上游。公共调用日志继续只保存操作元数据，不保存请求或响应正文。

下载失败即使使用 HTTP 200 的业务错误结构，也会进入现有错误详情，不能当成视频上传。自定义视频轮询遇到 HTTP 或网络错误停止自动轮询，保留原任务 ID 和诊断；正常 `queued`、`unknown`、`in_progress` 等中间状态仍按模板处理。不会自动重新创建生成任务或切换模型。

## 验证

免费 fixtures 覆盖 400/401/403/429、非 JSON、嵌套错误、三个失败阶段、请求 ID、完整正文与截断、凭据与签名链接脱敏、双账号归属、公共日志，以及正常二进制下载和旧协议回归。现有界面通过隔离浏览器检查详情显示。具体结果见 `evidence/upstream-errors-local.json`；[最终 CI 40297564050](https://github.com/ruoyeyu/ICAN/actions/runs/40297564050) 已通过；固定 digest、扫描及匿名核验见 [发布记录](evidence/upstream-errors-publication.json)。

未调用付费生成，没有修改部署服务器。模拟结果不能判断某个实际供应商的 401 原因；部署后正常提交产生的脱敏详情才用于定位该次失败。

## 更新与回滚

本次没有数据库迁移、模板格式变更或依赖变更，不重写账号、素材、渠道、用户配置或加密密钥。更新继续使用原数据目录和原密钥，仅替换 Compose 中固定 digest 的镜像。更新前按部署文档备份数据和密钥、记录旧 digest；回滚时恢复旧 digest，按[部署与回滚流程](ghcr-deployment.zh-CN.md)拉取、校验镜像，再使用原 Compose 和环境文件重建容器，不编译源码。不要清空卷、重新初始化账号或生成新密钥。旧镜像能保留现有字符串格式的任务详情，但不具备本次完整错误展示修复。
