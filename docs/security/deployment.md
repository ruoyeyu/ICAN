# 部署门槛、迁移、备份与回滚

当前候选代码不获准替换 `hb.lightnest.cn`。原 Nginx 静态站、Basic Auth 和公开参考文件路由保持原状。以下步骤不自动执行服务器操作。

用户已选择 Docker 部署，具体运行顺序和只读容器检查见 [docker-operations.md](docker-operations.md)。Compose 只接受预加载镜像，镜像引用必须由检查器核对为不可变摘要；不自动在服务器构建或拉取最新版本。

## 先完成的门槛

1. 由用户确认真实行为边界，再实现和验收：单文件上传、总请求体、账号/全站容量、并发生成与后台 worker、下载大小、重试和超时。不因“经验值”静默改变现有值。当前上传和若干正文读取仍使用内存 `ReadAll`，后台任务可启动较多 goroutine，这是明确的资源耗尽阻断项，不能仅依靠容器内存上限宣布已修复。
2. `AUTH_ATTEMPTS_PER_MINUTE` 是单进程全站登录/注册/改密请求数上限，未配置时拒绝这些请求；需要按用户规模确认，不能视为每个 IP 的额度。多副本需统一限流策略。`MEDIA_LINK_TTL_SECONDS` 决定供应商参考素材授权寿命，未配置时拒绝签发；需覆盖供应商实际抓取窗口，且不能长到形成永久公开链接。测试用的 1000/60 不是部署建议。
3. Compose 的 CPU、内存、进程、临时目录和缓存限制均为必填占位值。先在独立测试目录和未使用端口启动，保留唯一管理通道。不得挂载 Docker socket、SSH 配置、宿主机根目录、运维凭据或其他站点数据。
4. 最终候选镜像已在独立 CI 构建，记录 Image ID、SBOM 和完整扫描（runtime-review.md）；生产部署时仍需对待发布镜像固定摘要，并复核现存中低危匹配和静态 native 库。按操作系统、平台、调用路径评估，阻断未修复且可达的高风险问题。验证非 root、只读根目录、写目录边界、退出信号、重启恢复和健康检查。仓库 CI 只构建和验证，不登录镜像仓库、不推镜像、不发布站点。
5. 专用容器网络仍需宿主机出站 ACL：阻断应用访问宿主机、其他容器/局域网、云元数据、IPv6 等旁路；只为必要 DNS 与经审批的管理员存储目的地例外放行。应用 HTTP 检查不能替代内核网络隔离。先确认现有网络与管理通道，再生成与该服务器匹配的规则，不盲目改防火墙。
6. 正式域名 HTTPS；PUBLIC_ORIGIN 必须精确匹配。Nginx 不转发任意客户端提供的 Host/转发头作为信任依据；接口使用同源 cookie 和服务端权限。代理访问日志只记录 `$uri`，不要记录带 grant、token、key 的 `$request_uri`、`$args` 或完整 `$request`。重审旧公开上传/读取路由，不能让它们绕过新素材权限。
7. 真实浏览器两账号跨设备验收；真实画境合同和历史任务验收。付费测试前列出调用次数及总价并取得授权，先使用已有任务/fixture。

## 密钥及首次初始化

`.env.example` 不含可用凭据。DATA_ENCRYPTION_KEY 为独立随机 32 字节的标准 Base64；JWT_SECRET 至少 32 字节独立随机值。不要重复使用数据库/SSH/管理员密码。首次启动显式指定管理员密码，后续环境变量不自动重置已有管理员。

密钥与数据库分别备份；丢失加密密钥将无法恢复个人 API 配置。生产密钥不能出现在 Git、CI 输出、Docker build ARG、镜像层或应用日志。只在运行时注入，限制操作系统访问。容器内部数据目录交给 UID/GID 10001，进程 umask 077；Rootless/用户命名空间的宿主机属主需按实际映射验证。

推荐默认使用服务器本地媒体。若管理员改用 S3/WebDAV，必须检查存储桶/服务自身为私有；应用配置拒绝公开访问基址，但无法改变已经公开的桶权限。私网例外只限精确 WebDAV 来源，仍不允许回环/元数据。

## 数据迁移可行性与备份

本环境缺少旧 HB 源码、浏览器 IndexedDB 导出、服务器媒体目录、api.txt 和旧数据库。不能保证旧静态站的数据、Basic Auth 身份和新账号模型可直接对应。

- 在切换前，保存原站文件、Nginx/认证配置、公开参考素材目录、原 API 适配代码与未提交补丁；若有数据库，以一致性备份方式同时保存 SQLite 数据库及 WAL/SHM 状态，优先停写后用 SQLite backup 接口。
- 备份不进入 Web 根目录、不挂给应用、不放公开仓库。加密、异地保存并实际恢复一次；保留媒体对象与数据库索引的一致快照及校验和。
- 建立旧用户 → 新账号映射，不把同名 Basic Auth 用户直接视为新账号。先导入到隔离的临时库，核对画布/生成记录/素材归属、数量、引用路径、格式及缺失对象。
- 上游数据库：users 增加 token_version，新增 login_sessions 与 invitations，storage_objects 增加 share_version。旧登录 JWT 不接受。邀请码表只存摘要。
- user_configs 的 model_config/storage_provider 及 settings.private 由明文 JSON 改为 AES-GCM 密文。旧明文会明确报错，不自动降级。需要针对备份副本执行一次显式转换，核对账号绑定和解密结果后才可上线；本候选版没有对未知旧库执行或宣称完成转换。
- HTML/SVG/未知文件不能作为可执行同源内容迁入。私有媒体不得沿用旧公开 URL 的访问假设。可撤销供应商链接按需签发，旧永久链接的停用需提前核实在途任务。
- 保留已有任务 ID、上游任务 ID、模型和渠道归属；用历史任务验证状态恢复，不因迁移自动重新提交付费生成。

## 分阶段切换与回滚

只有全部安全、功能、备份和回滚门槛通过后，才利用用户已给出的条件部署授权切换站点。

先运行独立临时实例并验收，再冻结旧站写入、做最终备份、按已验证方案迁移；短暂维护窗口内修改反向代理指向新实例。保留原站目录、配置和镜像，不能在迁移时删除旧文件。

失败时先停新实例写入，恢复原 Nginx 配置及已备份静态站/认证配置，检查原站登录和素材读取。需要回滚数据时只恢复到明确批准的备份点，并单独处理切换期间的新写入，避免把两套格式互相覆盖。新旧加密数据库不能混用。每次演练记录触发条件、命令、备份校验、恢复用时和验证结果。
